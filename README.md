# AVRO! — Taste the Sunrise

A scroll-driven product hero for AVRO! cold drinks, built with Next.js and TypeScript. React renders the page at build time only: the browser gets static HTML, one stylesheet and a 7 KB script. One snap-scroll step per drink: the cup tumbles out, the landscape changes through an iris that opens from the cup, ingredients are thrown out of it, and the headline, caption and callouts follow.

## Getting started

```bash
npm install
npm run dev
```

Open <http://localhost:3000>.

| Script              | What it does                              |
| ------------------- | ----------------------------------------- |
| `npm run dev`       | Development server with fast refresh (rebuilds the engine on change) |
| `npm run build`     | Builds the engine, then the static site   |
| `npm run build:engine` | Bundles the browser script alone        |
| `npm run start`     | Serve the production build                |
| `npm run lint`      | ESLint (next/core-web-vitals + TypeScript) |
| `npm run typecheck` | `tsc --noEmit`                            |
| `npm run check`     | Typecheck + lint                          |
| `npm run images`    | Rebuild `public/` from the originals in `assets/` |

Requires Node 20.9 or newer.

## Configuration

Copy `.env.example` to `.env.local` and set `NEXT_PUBLIC_SITE_URL` to the canonical origin. It feeds the Open Graph tags, `robots.txt` and `sitemap.xml`.

## Menu

`/menu` lists every drink in [`src/data/drinks.ts`](src/data/drinks.ts) as a hairline grid of cards (number, cup, "Taste the …" in the drink's accent colour, name, note, tags). Each card links to that drink's step on the home page. Cups beyond the first row load lazily, so adding drinks costs nothing on first paint; on phones the cards collapse to rows.

## About and Contact

`/about` and `/contact` are static pages in the hero's visual language (night, glow, corner brackets) set in Persian, right-to-left, with Vazirmatn from `next/font`. Their copy lives in [`src/data/venue.ts`](src/data/venue.ts); the shared frame is [`Shell.tsx`](src/components/site/Shell.tsx). Like the home page they ship no JavaScript.

## Editing the menu

Everything a drink needs lives in one object in [`src/data/drinks.ts`](src/data/drinks.ts). To add a drink:

1. Drop a cup photo (transparent WebP, 464×640) in `assets/cups/` and a 1668×943 landscape in `assets/backgrounds/`.
2. Add any new ingredient cut-outs to `assets/sprites/` and register them in `src/data/sprites.ts` with their pixel size.
3. Run `npm run images` to regenerate `public/`.
4. Append a `Drink` entry. Image paths are written without an extension; the page serves AVIF and falls back to WebP. Ingredient positions (`bits`) are `[sprite, centerX, centerY, width, rotation, blur]` in artwork pixels of the 1668×943 scene; the cup sits at (848, 494).

`fall` lists the sprites that drift through the air and burst out of the cup on arrival; `petals` is a fallback list of flat colours for drinks without a `fall` set. Assign `PLANTATION_SIDES` to a drink's `sides` to frame it with foreground plants.

## How the motion works

- The scene is authored at 1668×943 and cover-fitted; `--u` is one artwork pixel in CSS pixels, so every element is positioned in source coordinates and scales with the viewport.
- `scroll-snap` on the document plus one `100svh` section per drink turns the wheel into a stepper; a `scroll` listener maps `scrollY` to the drink index and calls `go(n)`.
- `go(n)` cancels whatever is in flight and runs the swap with the Web Animations API, so fast scrolling never leaves stale timers or half-finished states.
- A single `requestAnimationFrame` loop drives pointer parallax, the cup's 3D tilt and the canvas "air" (dust motes, falling leaves, confetti).
- `prefers-reduced-motion` collapses every transition to an instant state change and disables the canvas, drops and shockwave.

## Responsive layout

Three viewport classes, each handled by its own media query in [`hero.css`](src/components/hero/hero.css):

- **Portrait** (`max-aspect-ratio: 1/1`) — the cover-fitted artwork shows only its middle, so the composition is pulled in: the cup scales to 78% and moves up (`--cs`, `--cty`), the ingredients are drawn in around it (`--bsx`, `--bsy`, `--bk`), and the callouts follow the cup because they are anchored to its centre. The engine reads these knobs so throws and the iris still start at the cup.
- **Narrow** (`max-width: 820px`) — the primary links move into the full-screen menu behind the burger ([`Menu.tsx`](src/components/hero/Menu.tsx)), the rail keeps only its bars with 32px tap targets, and on portrait phones the headline stacks.
- **Short landscape** (`max-height: 560px`) — smaller type and nav, cup at 92%, so a phone held sideways keeps the desktop arrangement.

`--pad-x`/`--pad-y` include the safe-area insets, so the frame and type stay clear of notches and the home indicator.

## Performance

The opening frame ships only what it shows: one landscape (AVIF, ~66 KB, or a ~31 KB centre crop on phones), one cup (~17 KB), seven small sprites, the logo, two font files, 6 KB of CSS and a 7 KB script — about 155 KB in ~16 requests on desktop and ~120 KB on a phone, against ~1.5 MB for the original single-file page.

- **No framework JavaScript.** The home page is built with `unstable_runtimeJS: false`, so React only runs at build time. The browser script is `src/components/hero/client.ts`, bundled by esbuild into `public/hero.js` and content-hashed through its query string so it can be cached for a year.
- **Portrait crops.** Tall screens only ever see the middle of the landscape, so they load a 750×943 centre crop, positioned to land exactly where the full image would.
- **Per-drink loading.** Only the first drink's artwork is in the HTML. Every other image carries its sources as `data-*` attributes; the engine's `warm(n)` turns them into real sources for the next drink during browser idle time, and for both neighbours after each swap. A cold jump (rail button, deep link) loads on demand.
- **AVIF with WebP fallback, no JavaScript needed.** Cups and the logo use `<picture>`; CSS backgrounds use `image-set()` with `type()` behind an `@supports` guard, so browsers without either get plain WebP.
- **No double downloads.** The cup relighting mask reuses whichever cup encoding the browser chose (`img.currentSrc`) instead of a separate mask file.
- **Cheap canvas.** Dust motes draw a pre-rendered radial sprite instead of building a gradient per particle per frame.
- **Preload hints** for the first landscape and cup, fonts self-hosted through `next/font`, one-year immutable caching on all artwork.

## Deployment

The site is fully static (`next build` prerenders every route). Deploy to Vercel with defaults, or run `npm run build && npm run start` behind any Node host. Artwork under `/backgrounds`, `/cups`, `/sprites`, `/sides` and `/brand` is served with a one-year immutable cache; rename a file if you replace it.
